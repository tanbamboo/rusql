## [Unreleased]

### Added

- **M166** — `SIGNAL SQLSTATE` inside stored procedure bodies raises ERR packets with user `MESSAGE_TEXT`, optional `MYSQL_ERRNO`, and the declared SQLSTATE (default errno **1644** when `MYSQL_ERRNO` omitted). `RESIGNAL` outside a condition handler is errno **1645** (i18n) until M170 handlers. Not `GET DIAGNOSTICS` or handler `RESIGNAL`. Tests: `signal` in `rusql-sql` / `rusql-executor` / `rusql-server`; mysql-diff `procedure_signal` (#318).
- **M165** — `CREATE PROCEDURE` accepts `OUT` / `INOUT` parameters; `CALL p(@var)` assigns back via user variables (M82). `OUT`/`INOUT` call arguments must be user variables (errno **1414**, i18n); `IN` procedures unchanged. `SHOW CREATE PROCEDURE` and `information_schema.PARAMETERS` list `OUT`/`INOUT` modes. Not `SIGNAL` (M166), cursors (M169), or function `OUT` params. Tests: `procedure_out` in `rusql-sql` / `rusql-executor` / `rusql-server`; mysql-diff `procedure_out_inout` (#317).
- **M164** — `GET_LOCK(name, timeout)` with `timeout > 0` blocks up to that many seconds (whole seconds; negative timeout waits until free). `timeout 0` stays non-blocking (`1`/`0`). `RELEASE_LOCK` from the holder wakes waiters; disconnect / `COM_RESET_CONNECTION` / `COM_CHANGE_USER` release session locks (M118). `IS_FREE_LOCK(name)` returns `1`/`0`; `IS_USED_LOCK(name)` returns the holder connection id or SQL NULL when free. NULL/empty names errno **3057**; names longer than 64 bytes errno **1470** (i18n). Not InnoDB row locks. Tests: `get_lock_timeout` in `rusql-core` / `rusql-executor` / `rusql-server`; mysql-diff `get_lock` extended (#316).
- **M163** — Session `LOCK TABLES t READ|WRITE` / `UNLOCK TABLES` (MySQL table metadata locks MVP). `WRITE` blocks other sessions' readers and writers until `UNLOCK TABLES` (errno **1205** after `innodb_lock_wait_timeout`, i18n). `READ` allows concurrent `SELECT`, blocks writers. Unknown table errno **1146**; tables not named in `LOCK TABLES` errno **1100**; DML on a `READ`-locked table errno **1099** (i18n). `LOCK TABLES` implicitly commits an open transaction. Not `READ LOCAL`, `FLUSH TABLES WITH READ LOCK`, or views/temp tables. Tests: `lock_tables` in `rusql-storage` / `rusql-executor` / `rusql-server`; mysql-diff `lock_tables` (#315).
- **M162** — XA two-phase transactions: `XA START` / `END` / `PREPARE` / `COMMIT` / `ROLLBACK` / `XA RECOVER` with single-branch quoted xids. `PREPARE` persists pending DML in additive WAL `xa_prepare` records (fsync); restart leaves prepared branches in `XA RECOVER` until `COMMIT` or `ROLLBACK`. Illegal state transitions errno **1399** (i18n). Ordinary `BEGIN`/`COMMIT` unchanged. Not `XA JOIN`/`RESUME`/`COMMIT ONE PHASE` or distributed XA. Tests: `xa` in `rusql-storage` / `rusql-server`; mysql-diff `xa_transactions` (#314).
- **M161** — Gap / next-key locks (InnoDB RR MVP): ADR [adr-m161-gap-next-key-locks.md](docs/en/architecture/adr-m161-gap-next-key-locks.md). Under **REPEATABLE READ** or **SERIALIZABLE**, `SELECT … FOR UPDATE` with a **single-column PRIMARY KEY range** (`BETWEEN` or bounded `AND` compares on the PK) takes a gap lock on that interval plus row locks on scanned rows. Concurrent `INSERT` of a PK inside the interval blocks until the holder `COMMIT`/`ROLLBACK` or `innodb_lock_wait_timeout` (errno **1205**, i18n). M160 deadlock detection includes gap waits (errno **1213**). **READ COMMITTED** keeps record locks only. MVP: literal `INSERT … VALUES` pre-wait on server; not full InnoDB lock matrix, `FOR SHARE` gaps, or multi-column PK. Tests: `gap_lock` in `rusql-storage` / `rusql-server` (#313).
- **M160** — Row-lock wait-for cycles are detected on the M157 `RowLockRegistry` (not only `innodb_lock_wait_timeout`). When two transactions lock rows in opposite order, the **younger** session (higher connection id in the cycle) is rolled back with errno **1213** (i18n); the other proceeds. Victim txn state and row locks are released on the server; connections stay open. Not InnoDB deadlock weight heuristics, `SHOW ENGINE INNODB STATUS`, or gap locks (M161). Tests: `deadlock` in `rusql-storage` / `rusql-server` (#312).
- **M159** — **SERIALIZABLE** isolation (M84 overlay) now changes engine behavior: REPEATABLE READ snapshot plus implicit **`FOR UPDATE`** row locks on plain `SELECT` over base tables with a single-column PRIMARY KEY (documented MVP; not InnoDB next-key/gap locks — M161). Concurrent `UPDATE` on locked rows waits like explicit `FOR UPDATE` (M157). `READ COMMITTED` / default RR unchanged. Not gap-lock phantom prevention on inserts into unlocked ranges, `FOR SHARE` under SERIALIZABLE, or JOIN/derived-table implicit locks. Tests: `serializable` in `rusql-storage` / `rusql-server`; mysql-diff `serializable_isolation` (#311).
- **M158** — Explicit transactions honor `@@transaction_isolation` from M84: default **REPEATABLE READ** keeps the M32 MVCC snapshot for the transaction; **READ COMMITTED** refreshes committed reads at each statement boundary so a second `SELECT` in the same `BEGIN` … `COMMIT` sees rows committed by other connections. `READ UNCOMMITTED` does not enable dirty reads; `SERIALIZABLE` still uses snapshot semantics until M159. Not gap/next-key locks or autocommit behavior changes. Tests: `read_committed` in `rusql-storage` / `rusql-server` (#310).
- **M157** — `SELECT … FOR UPDATE` on tables with a single-column PRIMARY KEY takes exclusive row locks until `COMMIT`/`ROLLBACK` (or autocommit statement end). A second connection’s conflicting `UPDATE` on the same row waits until the holder finishes or `innodb_lock_wait_timeout` (default 50s, `SET SESSION innodb_lock_wait_timeout`) elapses with errno 1205 (i18n). M85 syntax (`FOR SHARE`, `NOWAIT`, `SKIP LOCKED`) is still accepted; `FOR SHARE` / share locks remain non-blocking; `NOWAIT`/`SKIP LOCKED` do not change wait behavior yet. Not gap/next-key locks (M161), `SKIP LOCKED` errno 3572, or tables without a single-column PK (no row lock). Server tests: `for_update_wait` (#309).
- **M156** — `information_schema.COLUMNS` adds `COLUMN_DEFAULT`, `EXTRA`, and `COLUMN_KEY` for ORM migrators (appended to the existing M12 column set). `EXTRA` includes `auto_increment` and `VIRTUAL GENERATED` when catalog metadata exists (M146). `COLUMN_KEY` reflects `PRI` / `UNI` / `MUL` from primary keys, unique indexes, secondary indexes, and foreign-key columns. Unset defaults are SQL NULL (empty protocol cell). Not full MySQL 8.0 `COLUMNS` (charset name, `GENERATION_EXPRESSION`, `DEFAULT_GENERATED` in `EXTRA`, etc.). mysql-diff suite `information_schema_columns_extra` (#308).
- **M155** — `RENAME TABLE t1 TO t1_old, t2 TO t1` renames multiple table pairs in one statement (atomic swap idiom). Unknown source table is errno 1146; target name already occupied (and not also renamed in the same statement) is errno 1050; partial apply on error is forbidden. Standalone `RENAME TABLE` is parsed in `rusql-sql` (sqlparser 0.53 lacks it); `ALTER TABLE … RENAME TO` remains supported for a single table. Not cross-database rename beyond existing `db.table` resolution, view rename, or `information_schema` renames. mysql-diff suite `rename_table_multi` (#307).
- **M154** — `CREATE TABLE … LIKE` copies column definitions (including PRIMARY KEY, defaults, CHECK, VIRTUAL generated columns) into an empty table; FOREIGN KEY, RANGE partitioning, and secondary indexes are not copied. `CREATE TABLE … AS SELECT` infers column types from the result set and inserts selected rows (no PK unless declared). Unknown LIKE source is errno 1146; `CREATE TABLE IF NOT EXISTS` is a no-op when the target table already exists (documented). Not `LIKE` on views, tablespace clauses, or `SELECT *` CTAS. mysql-diff suite `create_table_like_ctas` (#306).
- **M153** — mysqldump-style `ALTER TABLE … ADD INDEX` / `ADD UNIQUE` / `DROP INDEX` and standalone `DROP INDEX idx ON tbl`. Executor handles `AddConstraint` index forms, `DropConstraint`, and `DropPrimaryKey`; `drop_index` + `validate_unique_index` on storage with WAL `drop_index`. `ADD UNIQUE` and `CREATE UNIQUE INDEX` enforce uniqueness on `INSERT`/`UPDATE` (errno 1062). SQL rewrites in `rusql-sql` for dump-only `DROP INDEX` spellings. Not `ALGORITHM`/`LOCK` or fulltext. mysql-diff suite `alter_table_index` (#305).
- **M152** — RANGE table partitioning MVP (`PARTITION BY RANGE (col) (PARTITION … VALUES LESS THAN …)`). ADR: [docs/en/architecture/adr-m152-range-partitioning.md](docs/en/architecture/adr-m152-range-partitioning.md). Catalog `RangePartitionMeta` in `TableMeta` / WAL; per-partition heap buckets; `INSERT` routes by partition key; `SELECT` with equality on the key reads one partition; EXPLAIN `Extra` shows `partitions: p0`. sqlparser strip/validate in `rusql-sql` (HASH/LIST/KEY rejected, i18n). Not subpartitions, exchange, or non-INT bounds. mysql-diff suite `partition_range` (#304).
- **M151** — Functional indexes `INDEX ((expr))` on `CREATE TABLE` and `CREATE INDEX` (MySQL 8.0.13+ MVP). One expression per index; supported keys are column identifiers with `+`, `-`, `*`, `/`, and numeric literals. Equality lookups (`WHERE expr = const`) use the index (EXPLAIN `type=ref` and heap `scan_eq_prefix`). `INSERT`/`UPDATE` maintain functional keys; unknown functions error at DDL (i18n). Inline `CREATE TABLE … INDEX ((expr))` is stripped at parse time and created after the table (single COM_QUERY, no multi-statement split). WAL reuses the legacy single-column `CreateIndex.column` field with an internal marker (no new WAL variant). Not descending functional indexes, prefix/range on expressions, or covering-index claims. mysql-diff suite `functional_index` (#303).
- **M150** — `INVISIBLE` columns and indexes (MySQL 8.0.23+). Column flag in catalog/WAL; `SELECT *` omits invisible columns; explicit column references unchanged. `INSERT` requires values for invisible columns without `DEFAULT` (errno 1364, i18n). `SHOW CREATE TABLE` emits `INVISIBLE`. `CREATE INDEX … INVISIBLE` sets `IndexMeta.invisible`; planner and heap index scans ignore invisible indexes. DDL rewrite in `rusql-sql` until sqlparser gains native `INVISIBLE`. Not `ALTER … SET INVISIBLE` or functional indexes (M151). mysql-diff suite `invisible_column` (#302).
- **M149** — Column `DEFAULT` literals and `DEFAULT (expr)` (MySQL 8.0.13+) persist `ColumnDefault` in catalog/WAL (`serde(default)`). `INSERT` omitting a column (or `VALUES (DEFAULT)`) evaluates the default with the same expression engine as generated columns; `UPDATE … SET col = DEFAULT` restores the catalog default (per-row when needed). Invalid default expressions error at `CREATE TABLE` (i18n parse errors). `SHOW CREATE TABLE` / `DESCRIBE` show defaults. `CURRENT_TIMESTAMP` on `DATETIME`/`TIMESTAMP` defaults use `NOW()`. Not `ALTER TABLE … ALTER COLUMN … SET DEFAULT`, defaults on VIRTUAL generated columns, or evaluating defaults on `UPDATE` without the `DEFAULT` keyword. mysql-diff suite `default_expr` (#301).
- **M148** — `ENUM('a',…)` and `SET('a',…)` column types store canonical member strings in heap rows. `INSERT`/`UPDATE` validate membership; invalid values with default `@@sql_mode` (`STRICT_TRANS_TABLES`) are errno 1265 (i18n). Without strict mode, invalid `ENUM` becomes empty string and invalid `SET` members are dropped. `SET` values are stored in declaration order (`'b,a'` → `'a,b'`). `SHOW CREATE TABLE` reconstructs member lists (preserving member case). Not numeric ENUM index literals, `ALTER … MODIFY` validation beyond catalog type string, or `FIND_IN_SET`. mysql-diff suite `enum_set_types` (#300).
- **M147** — `CHECK (expr)` on `CREATE TABLE` (column- and table-level, optional `CONSTRAINT name`) persists `CheckConstraintMeta` in catalog/WAL (`serde(default)`). `INSERT`/`UPDATE` evaluate the expression per row (including VIRTUAL generated columns materialized for the check); violations are errno 3819 (i18n). `SHOW CREATE TABLE` reconstructs column and named table checks. `information_schema.TABLE_CONSTRAINTS` CHECK rows unchanged (M119 scope). Not `CHECK NOT ENFORCED`, `ALTER TABLE … ADD CHECK`, or CHECK on `SELECT`. mysql-diff suite `check_constraint` (#299).
- **M146** — VIRTUAL generated columns (`col AS (expr) [VIRTUAL]`) persist `VirtualGeneratedColumn` in catalog/WAL (`serde(default)`); heap rows omit stored values for generated slots. `SELECT` / `SHOW CREATE TABLE` compute or reconstruct `AS (expr) VIRTUAL`. Explicit `INSERT`/`UPDATE` of a generated column is errno 3105 (i18n); omitting the column on `INSERT` computes on read. `STORED` / `PERSISTENT` generated columns error (i18n). Not full generation-expression function parity. mysql-diff suite `generated_column_virtual` (#298).
- **M145** — `EXPLAIN FORMAT=JSON SELECT …` returns one `EXPLAIN` column with a documented JSON stub (`query_block` with nested `table.access_type`, `table_name`, optional `key`, and `rows_examined_per_scan`). Plain text `EXPLAIN` (M49) is unchanged. `EXPLAIN ANALYZE` / `VERBOSE` / `QUERY PLAN` and `EXPLAIN FORMAT=GRAPHVIZ` still error. Not full MySQL 8.0 optimizer JSON, live `cost_info`, or `EXPLAIN FOR CONNECTION`. mysql-diff suite `explain_json` uses `compare_output: false` because MySQL's tree differs (#297).
- **M144** — Two-table `INNER JOIN` forms of `UPDATE` and `DELETE`: `UPDATE t1 INNER JOIN t2 ON … SET t1.c = t2.c` updates matching rows in `t1` only; `DELETE t1 FROM t1 INNER JOIN t2 ON …` deletes matching rows in `t1` only. Unknown alias/column errors; single-table `UPDATE`/`DELETE` unchanged. Requires single-column primary key on the target table. Not `DELETE t1, t2 FROM`, multi-target delete, `UPDATE … FROM`, `FULL OUTER`/`LEFT`/`RIGHT` join DML, or `LIMIT` on multi-table `UPDATE`. mysql-diff suite `multi_table_dml` (#296).
- **M143** — `INSERT INTO t SET col=expr, …` is equivalent to column-list `INSERT INTO t (col, …) VALUES (expr, …)` for one row. Unknown column errors match plain `INSERT`; duplicate PRIMARY KEY is errno 1062. `INSERT IGNORE … SET` skips PK conflicts like `INSERT IGNORE … VALUES`. M68 `INSERT … SELECT` / `ON DUPLICATE KEY UPDATE` and M111 `REPLACE INTO` are unchanged. Not multi-table INSERT. mysql-diff suite `insert_set` (#295).
- **M142** — `GREATEST(expr[, …])` and `LEAST(expr[, …])` require two or more arguments; any NULL argument yields SQL NULL (default `sql_mode`; not `HIGH_NOT_PRECEDENCE` / `IGNORE` NULL variants). Fewer than two arguments is errno 1582 (i18n). Mixed quoted-string and numeric literals compare as strings; all-numeric literal lists compare as numbers (MySQL 8.0). Not window `GREATEST`/`LEAST` or scalar `MIN`/`MAX` over varargs. mysql-diff suite `greatest_least` (#294).
- **M141** — `TRIM`/`LTRIM`/`RTRIM` (default whitespace trim; `TRIM([BOTH|LEADING|TRAILING] remstr FROM str)` removes characters in `remstr`). `REPLACE(str, from, to)` replaces all occurrences; empty `from` returns `str` unchanged (MySQL 8.0). `SUBSTRING_INDEX(str, delim, count)` returns the first/last `count` delimited segments (negative `count` from the right). M113 `SUBSTRING`/`ROUND`/`DATE_ADD` unchanged. Not `REGEXP`/`RLIKE` or collation-aware REPLACE beyond utf8mb4 text compare. mysql-diff suite `string_pack` (#293).
- **M140** — `DATE_SUB`/`SUBDATE` with `INTERVAL` (same type rules and MONTH/YEAR 30/365-day approximation as M113 `DATE_ADD`). `DATEDIFF(left, right)` returns date-only day difference with MySQL sign. `DATE_FORMAT` supports `%Y`, `%m`, `%d`, `%H`, `%i`, `%s`, and `%%` only; other specifiers error. Not `STR_TO_DATE`, full strftime `DATE_FORMAT`, or `TIMESTAMPDIFF`/`EXTRACT`. mysql-diff suite `date_pack` (#292).
- **M139** — `CONVERT(expr USING utf8mb4)` and `CONVERT(expr, CHAR CHARACTER SET utf8mb4)` return the expression text when the value is already utf8mb4 (identity conversion). Unknown charset is errno 1115 (i18n, same family as M114). Existing `CAST(x AS CHAR)` and numeric `CAST` are unchanged. Not `CONVERT(expr, type)` without `USING` / `CHARACTER SET`, latin1 transcoding, or `SET NAMES` changes. mysql-diff suite `convert_charset` (#291).
- **M138** — MySQL table-value constructor `VALUES ROW(1), ROW(2)` as a top-level query or derived table in `FROM` returns rows with default column names `column_0`, `column_1`, … Column count mismatch across `ROW()` lists is errno 1136 (i18n). `INSERT … VALUES` row lists are unchanged. Not `TABLE t` syntactic sugar or CTE substitution. mysql-diff suite `values_row` (#290).
- **M137** — Two-table `FULL OUTER JOIN` / `FULL JOIN … ON` returns matched rows plus NULL-padded unmatched rows from both sides (LEFT JOIN plus unmatched RIGHT). `INNER` / `LEFT` / `RIGHT` joins are unchanged. `ON` is required (same as existing outer joins). `USING` and natural join stay unsupported. Docker MySQL 8.0 rejects `FULL OUTER JOIN` syntax; rusql implements the documented LEFT ∪ unmatched-RIGHT row set. mysql-diff suite `full_outer_join` (#289).
- **M136** — `SELECT … EXCEPT SELECT …` returns the distinct set difference of both SELECT results (left rows that never appear on the right, once, left-side order). `SELECT 1 EXCEPT SELECT 1` returns zero rows; `SELECT 1 EXCEPT SELECT 2` returns `1`. `EXCEPT ALL` is a multiset difference: a 2-row left vs 1-row right fixture keeps one leftover left duplicate. Column count mismatch is errno 1222 (i18n). `UNION` / `UNION ALL` / `INTERSECT` are unchanged. Not `INTERSECT ALL` or `MINUS`. mysql-diff suite `except` (#288).
- **M135** — Window `LAG` / `LEAD` / `SUM() OVER`: `LAG(col)` / `LAG(col, 1)` / `LEAD(col)` use offset 1 by default; the first `LAG` and last `LEAD` are SQL NULL (optional third-arg default is used when the offset is out of range). `SUM(n) OVER (PARTITION BY g ORDER BY id)` is a running sum per partition without requiring a `ROWS` clause (default frame is `UNBOUNDED PRECEDING` … `CURRENT ROW` when `ORDER BY` is present, and the whole partition when it is not). Explicit `ROWS BETWEEN` frames from M129 apply to `SUM`. Wrong `LAG`/`LEAD`/`SUM` arity is errno 1582 (i18n). Ranking `ROW_NUMBER` / `RANK` / `DENSE_RANK` are unchanged. Not `NTH_VALUE` / `CUME_DIST` / `RANGE` / named windows (M203). mysql-diff suite `lag_lead_sum_over` (#287).
- **M134** — `JSON_OBJECT(key, val[, …])` and `JSON_ARRAY([val[, …]])` construct JSON documents (`JSON_OBJECT('a', 1, 'b', 'x')` → `{"a": 1, "b": "x"}`; `JSON_ARRAY(1, 'x')` → `[1, "x"]`). `JSON_SET(doc, path, val[, …])` adds a missing last-component key when the parent object exists (`JSON_SET('{}', '$.a', 1)` → `{"a": 1}`) and replaces existing keys. Nested paths whose parent is missing are a no-op like MySQL 8.0 (`JSON_SET('{}', '$.a.b', 1)` → `{}`). Odd-length `JSON_OBJECT` args and incomplete `JSON_SET` pairs are errno 1582. NULL object keys are errno 3158. Invalid JSON documents are errno 3141 (i18n). Paths are the M115 subset. Not `JSON_REPLACE` / `JSON_REMOVE` / `JSON_TABLE` / full JSONPath. mysql-diff suite `json_object` (#286).
- **M133** — `JSON_UNQUOTE(json)` unquotes a JSON string (`JSON_UNQUOTE(JSON_EXTRACT('{"a":"x"}', '$.a'))` → `x`). `col->'$.a'` is `JSON_EXTRACT`; `col->>'$.a'` is `JSON_UNQUOTE(JSON_EXTRACT(...))` for the M115 `$.key` / `$.a.b` path subset. Missing path is SQL NULL. Invalid JSON is errno 3141 (i18n). Non-quoted text is returned as-is. M115 `JSON_EXTRACT` is unchanged. Not `JSON_OBJECT` / `JSON_ARRAY` / `JSON_SET` (M134), `JSON_TABLE`, or full JSONPath. mysql-diff suite `json_unquote` (#285).
- **M132** — `CREATE PROCEDURE name (IN x INT) …` persists `IN` parameters (`serde(default)` empty vec for old `programs.json` rows). `CALL name(literal)` substitutes matching `IN` args into the body (`CALL gap_p(3)` returns `3`). `SHOW CREATE PROCEDURE` reconstructs `IN x INT` instead of a forced empty `()`. Zero-arg procedures are unchanged. Wrong `CALL` arity is errno 1318. `information_schema.PARAMETERS` lists persisted `IN` rows (M121 scan). Not `OUT`/`INOUT` (M165), `SIGNAL` (M166), or CLI `DELIMITER` (M172). Wire tests send the full `BEGIN … END` `COM_QUERY`; mysql-diff suite `procedure_in_param` uses a single-statement body so the official CLI does not need `DELIMITER` (#283).
- **M131** — `SHOW ENGINE INNODB STATUS` returns MySQL-shaped columns (`Type`, `Name`, `Status`) with a non-empty i18n stub `Status` cell. This is not live InnoDB mutex/lock statistics (M193). Unknown engine names are errno 1286 (`ER_UNKNOWN_STORAGE_ENGINE`). `SHOW ENGINES` is unchanged. `SHOW ENGINE … MUTEX` and `SHOW ENGINE PERFORMANCE_SCHEMA STATUS` are not implemented. mysql-diff suite `show_engine_innodb_status` uses `compare_output: false` (#282).
- **M130** — `CREATE EVENT … DISABLE ON SLAVE` (and `ALTER EVENT … DISABLE ON SLAVE` / `ENABLE ON SLAVE`) persists `EventMeta.disable_on_slave` (`serde(default)`). `SHOW CREATE EVENT` reconstructs `DISABLE ON SLAVE`. rusql has no replica role yet, so the scheduler treats the flag as DISABLED (same skip as `DISABLE`) while `SHOW EVENTS` still lists the row (`Status` `SLAVESIDE_DISABLED`). Plain `ENABLE` / `DISABLE` without `ON SLAVE` are unchanged. Not replica `server_id` gating. mysql-diff suite `event_disable_on_slave` (#281).
- **M129** — Window `ROWS BETWEEN` frames on `ROW_NUMBER` / `RANK` / `DENSE_RANK`: `UNBOUNDED PRECEDING`, `CURRENT ROW`, `n PRECEDING`, and `n FOLLOWING` (including the `ROWS n PRECEDING` shorthand). Ranking functions ignore the peer set like MySQL 8.0, so framed ranks match unframed ranks. Illegal start/end pairs are errno 3585 (i18n). `RANGE` / `GROUPS` frames and named `WINDOW` clauses still error. Not aggregate `SUM() OVER` (M135). mysql-diff suite `window_frame_rows` (#280).
- **M128** — `SELECT … INTERSECT SELECT …` returns the distinct set intersection of both SELECT results (matching rows once, left-side order). `SELECT 1 AS n INTERSECT SELECT 1 AS n` returns one row `1`; disjoint sides return zero rows. Column count mismatch is errno 1222 (i18n). `UNION` / `UNION ALL` duplicate semantics are unchanged. Not `INTERSECT ALL` (rejected) or `EXCEPT` (M136). mysql-diff suite `intersect` (#279).
- **M127** — `WITH RECURSIVE cte AS (SELECT … UNION ALL SELECT … FROM cte …)` iterates the recursive UNION ALL member against the previous working rows (counting form `1,2,3` in generation order). Recursion past the documented `cte_max_recursion_depth` cap of 1000 is errno 3636 (i18n), not a hang. Non-recursive `WITH` (M69) is unchanged. Not `SEARCH` / `CYCLE`, cycle detection beyond the cap, or recursive DML. mysql-diff suite `with_recursive` (#278).
- **M126** — `SAVEPOINT name` / `ROLLBACK TO SAVEPOINT name` / `RELEASE SAVEPOINT name` are named savepoints inside a transaction. `ROLLBACK TO` restores the overlay at that point and keeps the transaction open (the savepoint remains; later savepoints are dropped). `RELEASE` drops the name; a following `ROLLBACK TO` is errno 1305. `SAVEPOINT` outside an explicit `BEGIN` starts a transaction (MySQL autocommit implicit start). Savepoints do not survive `COMMIT` / `ROLLBACK`. Not XA. mysql-diff suite `savepoint` batches SAVEPOINT+ROLLBACK TO on one CLI connection (#277).
- **M125** — Text `PREPARE name FROM 'sql'` / `EXECUTE name` / `DEALLOCATE PREPARE name` (and `DROP PREPARE`) store session-scoped named statements for `COM_QUERY` clients. `EXECUTE` returns the same result as running the stored SQL. Unknown names are errno 1243. Invalid SQL fails at `PREPARE`; SQL that parses but rusql cannot run fails at `EXECUTE` (documented). `COM_RESET_CONNECTION` / `COM_CHANGE_USER` clear the map. Binary `COM_STMT_*` ids are unchanged. Not `EXECUTE … USING` or `PREPARE … FROM @var`. mysql-diff suite `prepare_execute_text` batches PREPARE+EXECUTE on one CLI connection (#276).
- **M124** — `CREATE OR REPLACE VIEW` creates the view when missing and replaces the stored SELECT in place when it already exists. `SHOW CREATE VIEW` and querying the view use the new SQL. Replacing a base table of the same name is errno 1347 (`ER_WRONG_OBJECT`). Plain `CREATE VIEW` still errors on duplicate (M33). Not `ALTER VIEW`, ALGORITHM / DEFINER / SQL SECURITY, or materialized views. mysql-diff suite `create_or_replace_view` batches view DDL with SELECT on one CLI connection (views are session catalog, same as M33); `SHOW CREATE VIEW` uses `compare_output: false` because rusql omits ALGORITHM/DEFINER (#275).
- **M123** — `SHOW BINLOG EVENTS` (optional `IN 'log_name'`, `FROM pos`, `LIMIT`) lists real events from known `{data_dir}/binlog/binlog.NNNNNN` files with MySQL-shaped columns `Log_name`, `Pos`, `Event_type`, `Server_id`, `End_log_pos`, `Info`. With binlog enabled the first row is `Format_desc` from the file (not a stub). Unknown event types use `Event_type` `Unknown` and an empty Info cell. A missing binlog directory is a documented empty list. Unknown `IN` files are errno 1220. `SHOW BINARY LOGS` is unchanged. This is not mysqlbinlog tool compatibility. mysql-diff suite `show_binlog_events` uses `compare_output: false` because event payloads differ from Docker MySQL (#274).
- **M122** — `SHOW BINARY LOGS` (and MySQL synonym `SHOW MASTER LOGS`) returns MySQL-shaped columns `Log_name` and `File_size` over known `{data_dir}/binlog/binlog.NNNNNN` files. When binlog is enabled the current file is listed (at least `binlog.000001`); sizes are the on-disk length. A missing binlog directory is a documented empty list, not errno 1381. This is not mysqlbinlog tool compatibility. mysql-diff suite `show_binary_logs` uses `compare_output: false` because file names and sizes differ from Docker MySQL (#273).
- **M121** — `SELECT SPECIFIC_NAME FROM information_schema.PARAMETERS LIMIT 1` is a valid query (not errno 1146).
